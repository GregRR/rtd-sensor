# Characterized-R0 binary32 compatibility profile

This document records the empirical basis for extending the stable conformance-v1
`binary32_compatible` profile to the bounded characterized-reference-resistance
fixtures that use the already supported IEC 60751 PT-385 characteristic.

The published absolute tolerances are the same as the built-in profile:

| Capability | Output unit | Absolute tolerance |
| --- | --- | ---: |
| `conversion.temperature_to_resistance` | ohm | 0.002 Ω |
| `conversion.resistance_to_temperature` | degree Celsius | 0.001 °C |

These are interoperability tolerances. They are not calibration uncertainty,
RTD tolerance, or total measurement-uncertainty statements.

## Conformance scope

The binary32 claim is fixture-scoped. Conformance v1 publishes this profile only
for the successful `characteristic_model` fixtures using
`iec60751_pt385`:

- `calibrated_pt385_r0_99p5` — `R0 = 99.5 Ω`, -200 °C through 850 °C;
- `calibrated_pt385_nonnominal_r0` — `R0 = 100.123 Ω`, -50 °C through 200 °C;
- `calibrated_pt385_r0_502p5` — `R0 = 502.5 Ω`, -100 °C through 500 °C; and
- `calibrated_pt385_r0_995` — `R0 = 995 Ω`, -200 °C through 850 °C.

The fixture IDs are conformance subjects, not canonical built-in `model_id`
values. This profile does not imply binary32 compatibility for arbitrary custom
CVD coefficients, polynomial, piecewise-polynomial, or tabulated models.

## Independent single-precision path

The validation path uses `rtd_conformance_f32.c`, which stores model parameters,
characteristic coefficients, inputs, intermediate arithmetic, and inverse-search
state as C `float`. The inverse is bounded global bisection rather than Python's
curve-specific inverse implementation.

The stress program `characterized_r0_study.c` supplies its own binary64 PT-385
reference equation and drives the independent float consumer. It does not call
Python conversion code, call the binary64 C consumer, or calculate in binary64
and merely cast the final result to `float`.

The published fixture vectors remain generated by the validated Python reference
implementation and are separately executed by the C11 float runner. The stress
study therefore complements, rather than replaces, the public vectors.

## Stress population

The deterministic study evaluates a broader population than the fixture claims:

- nominal `R0` families of 100 Ω, 500 Ω, and 1000 Ω;
- 81 evenly spaced values from -5% through +5% around each nominal value;
- a 0.25 °C sweep over the full -200 °C through 850 °C PT-385 range;
- 300,000 additional deterministic random `(R0, temperature)` samples over the
  same R0 bands and temperature range; and
- 1,320,843 total forward/inverse cases.

These ±5% R0 bands are stress-study breadth, not eligibility bands. Only the
explicit fixtures listed under **Conformance scope** may claim
`binary32_compatible`; another characterized R0 value inside a studied band is
not covered unless it is separately added to the public fixture allowlist.

The committed fixture set additionally exercises full and narrowed validity
ranges, exact endpoints, representative negative and positive temperatures,
0 °C branch/reference behavior, inputs just outside declared ranges, non-finite
inputs, and non-positive resistance status semantics.

## Measured error envelope

The study was run on x86-64 with GCC 14.2 and Clang 17 at `-O0`, `-O2`, and
`-O3`. Builds using `-ffp-contract=fast` at `-O2` and `-O3` produced the same
reported maxima.

Across the 1,320,843-case study, the largest observed differences from the
binary64 reference were:

| Quantity | Maximum observed difference |
| --- | ---: |
| temperature → resistance | 0.0008449973288406909 Ω |
| resistance → temperature | 0.00028663770160619606 °C |

The published tolerances therefore retain margins of approximately 2.37× for
forward conversion and 3.49× for inverse conversion over the largest observed
differences in this study.

## Reference-resistance representation

The stress population treats each generated decimal `R0` as the reference value
and then converts that value to binary32 for the independent consumer. The
largest observed forward resistance effect attributable solely to this `R0`
representation step was:

```text
0.00023742236453472287 Ω
```

That representation effect is included in the total interoperability error
reported above. Calibration-certificate uncertainty, the number of significant
digits justified by a laboratory result, probe drift, lead resistance, ADC
error, and other measurement effects remain separate scientific concerns and
are not absorbed into this acceptance profile.

## Endpoint behavior

The float consumer retains the same four-ULP inverse endpoint guard documented
for the built-in binary32 profile. The guard exists only to preserve exact
endpoint-success semantics when a binary64 reference resistance and a
single-precision forward calculation round to adjacent binary32 values. It does
not widen a model's declared physical range.

The custom status vectors use resistance anchors 0.01 Ω outside the binary64
model endpoints, which remain unambiguously outside this representation guard.

## Reproduction

The repository test suite compiles and executes both the published characterized
fixture vectors and `characterized_r0_study.c` with an available C compiler.
Run the focused verification with:

```bash
uv run --locked pytest tests/test_c_conformance_consumer.py -v
```

The broader compiler/optimization matrix above is derivation evidence recorded
for this profile. Normal CI also uses tighter regression guards of 0.001 Ω
forward and 0.0004 °C inverse so the measured engineering margin cannot silently
collapse while remaining barely inside the broader public tolerance.
